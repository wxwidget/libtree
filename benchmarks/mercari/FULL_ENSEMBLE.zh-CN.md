## 最终到底融合几个模型

冻结矩阵有 **26 列预测**；其中 **9 个分支的权重大于 1e-15**。
其他极小数值权重也原样保留，没有偷偷删掉模型。

| LightGBM 校准管线 | 31.723558% |
| XGBoost 校准管线 | 24.906067% |
| LibTree 深度 5 校准管线 | 18.262506% |
| LibTree 深度 3 校准管线 | 17.407428% |
| 原冻结整体方案 | 4.027710% |

| 词干化稀疏网络，MSE | 0.196278% |
| 词干化稀疏网络，Huber | 0.137807% |

“分支”不等于独立模型。四个残差校准分支共享同一组上游专家和特征，每个分支的输出为：
**冻结的内层融合 + 冻结强度 × 残差修正**。

完整依赖图共 **32 个价格预测器**：原方案 7 个（Ridge、FM、4 个神经网络、1 个残差树模型），
新增专家 19 个（LSA 预测头 4 个、冻结向量预测头 3 个、序列网络 2 个、稀疏网络 9 个、
监督 MiniLM 1 个），新增校准器 6 个（4 个树模型、2 个非负 Ridge）。
词表、SVD 和类别映射属于另外的特征转换器。外层权重小，不代表上游推理成本已经消除。

## 最终训练怎样进行

全部官方训练数据分为 **1,395,326 条基础训练、87,209 条校准数据**，按商品分组、种子 44。
基础专家及词表只拟合基础数据；校准器只拟合校准数据。轮次、树数量、修正强度和两层权重
已经冻结，不再用最终校准标签选参数。

原方案的“已修正预测”只用作其外层分支。新校准器的特征使用原专家的**未修正融合**及元数据，
避免把原校准器学过的目标当作新校准器的输入。所有特征和预测都严格检查 ID、顺序及维度。

八个独立进程分别处理原方案、LSA、序列、分字段稀疏、联合稀疏、词干稀疏、冻结向量及监督微调。
进程结束后释放 TensorFlow／Torch 的 GPU 分配，避免跨框架占用叠加。
测试集每批最多 25,000 行；稀疏特征在预测头之间共享，用内存映射保存中间结果。
最终必须为样例提交表里的 **3,460,725 条商品**生成有限、非负价格。

公开 MiniLM 固定为 `srg9000/all-minilm-l6-v2/transformers/default/1`。
配置和 tokenizer 文件与研究时一致；权重文件通过该镜像快照的 Git LFS SHA-256 校验：
`53aa51172d142c89d9012cce15ae4d6cc0ca6895895114379cacb4fab128d9db`。
它是 Apache-2.0 许可的通用预训练初始化，不是上传的 Mercari 训练模型。
离线源码包包含未经修改的 Snowball 3.0.1 及其 BSD 许可。

这是已结束比赛的现代 GPU 练习。所有价格模型在同一个 Kernel 内重训和预测；
不宣称满足 2018 年的 CPU／运行时间限制，也不宣称获得当年的名次。
扩大训练集以及软硬件差异都可能改变成绩，最终必须看实际 private 分数。

## 已完成的功能验证

- Kaggle T4 的小规模完整流程：100 条训练记录、7 条构造测试商品，全部阶段完成，耗时 **170.41 秒**。
- 本地隔离 TensorFlow／Torch 环境，使用公开预训练模型，也已跑通完整 CPU 流程。
- 冒烟测试只验证训练、融合、导出、依赖和文件流程，不能作为效果或大规模性能证据。
- 冒烟文件名为 `SMOKE_ONLY_DO_NOT_SUBMIT.csv`，不允许提交。

本地发布验证为 **131 个不同测试通过，18 个 Mercari 模块的 2,258 条语句全部覆盖**。这是语句覆盖率，不是整个仓库或分支覆盖率。[验证 JSON](full-ensemble-verification.json)和[真实 Kaggle 冒烟报告](full-ensemble-smoke.json)保留原始证据。

## 复现与提交检查

[英文说明](FULL_ENSEMBLE.md#reproduction)给出完整命令。
先安装 `.[mercari,benchmark]` 和官方 `kaggle==2.2.4`，运行
`benchmarks.mercari_full_kernel.build(..., smoke=True)` 构建私有 GPU 冒烟 Kernel。
确认完整报告后，在新目录用 `smoke=False` 构建正式 Kernel。
本机直接运行可用 `python -m benchmarks.mercari_final --help`；
`--torch-python` 可指定隔离的 Torch 环境。

提交前检查完成状态、准确的源码哈希及版本、非冒烟报告、原始数据哈希、完整训练划分、
预训练权重哈希、全部阶段、冻结配置与权重、预测文件哈希和 3,460,725 行输出。
`benchmarks.mercari_ensemble.validate_hosted` 实现报告门禁，本地及 CI 测试也必须通过。
随后通过 `api.competition_submit_code` 指定准确的 Kernel 版本提交。

提交请求成功不等于评分完成。必须等到 `COMPLETE`，记录 public、private、源码与配置哈希。
遇到返回不明确的网络错误，先查已有提交回执，避免重复提交。
原始数据、模型、预测和传输文件继续放在 Git 忽略的 `benchmarks/runs/` 中。
