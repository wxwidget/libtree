# Mercari 原榜前三名：源码细节、经验与本轮落地

[English](TOP3.md) · [机器可读证据](top3-results.json) · [初学者指南](BEGINNER_GUIDE.zh-CN.md)

本报告核对的是**原比赛最终榜**：[历史截图][board]显示，前三名依次为
**Paweł and Konstantin（private 0.37758）、Mercaring（Nima & Chahou，0.38875）、
bird（0.39134）**。这些榜单分数不能与我们的本地复核分数直接比较。
已有文档引用的 Chenglong Chen／XNN 是第四名，不应混入“前三名”。

冠军源码固定在提交 `374301ad1c32cbc93dcc40313d5d7bb9c5503746`。
2026 年 10 月 18 日读取了前三名原帖和第二、三名公开 kernel；来源、内容摘要和
SHA256 保存在[证据清单](top3-results.json)。下文明确区分**作者报告的实验发现、
源码中可见的实现细节、我们的解释**。采用思路不等于复现原方案或取得原榜名次。

## 冠军：融合的基本单位是“数据表示”

[冠军原帖][first]的最终方案是 **3 种文本表示 × 每种 4 个稀疏 MLP**。
表示之间改变分词、词干、词／字符特征；同一表示内改变 Huber／软分桶分类损失、
二值／加权输入。将现有稀疏矩阵的非零值改为 1，相当于低成本获得另一个输入视角，
不必重新构造全部特征。

容易忽略的细节与经验：

- **数量需要与具体的词绑定。**“10 cards、5 dolls”不只是出现了数字 10 和 5，
  而是分别有多少卡片、多少玩偶。冠军增加了前置数字加权的词向量，并报告在一个
  数据视角上使用后，融合约改善 .001。这是作者的结果，不是本轮结果。
- **同一网络看到不同表示，可能比不同网络看到同一表示更互补。**
  标题、品牌、描述拼接还可以共享参数。我们的解释是：应比较单位时间内增加的
  误差互补性，而不能只数模型种类或随机种子数量。
- **训练计划决定预算里能放多大模型。**作者每轮增大 batch，并降低学习率，
  还刻意让较晚轮次的单模型过拟合来增加融合差异。这个经验不能照搬成审计集挑轮次；
  当前稀疏专家仍保留 selection 表现最好的检查点。
- **稀疏运算扩展性差时，按模型并行。**他们让每个模型使用一个核，同时训练四个，
  不同表示用顺序进程处理以回收内存。MXNet 版本还使用稀疏行更新。两个框架版本
  的分数差异，不能单独归因于“换框架就能提高泛化”。
- **融合还有截距与总权重自由度。**公开的 Lasso 融合含截距，权重也不必和为 1；
  作者记录了新模型被置零的情况。我们的正则化仿射融合支持检验这种自由度，
  同时约束截距和系数总量。

作者还记录了拼写纠正、“for [姓名]”特征、合并前的品类专用系统／残差建模、
混合专家和混合 FM／跳连结构等失败经验。这是其设置下的结果，不是普遍定律。
例如，我们已有残差产品校准在另一套融合中取得了实测收益。

## 亚军：不用昂贵序列模型也能构造交互

[亚军原帖][second]包含 Ridge、词稀疏网络、共享词嵌入的平均池化网络、字符稀疏网络。
作者明确说公开 kernel 与获奖提交**几乎相同**，公开版本是
**public .38888／private .38948，耗时 2,800 秒**。不能把它写成最终榜的 .38875。

最有特色的是 Ridge 的**无序词对**：标题加描述前 5 个词，排序去重后生成所有两两组合。
“red leather shoe”和“shoe red leather”具有相同词对；普通相邻 bigram 做不到这一点。

源码里还有原帖没有完整展开的细节：

- `create_bigrams` 先做词形还原、去停用词；如果两个词正向或反向拼接后，在训练集
  单词字典中存在，就用这个单词代替词对。我们的解释是：用训练词典连接
  “lip gloss”和“lipgloss”等写法。本轮**尚未实现**这种词典替换。
- 品牌／品类编码作为伪词加入标题，可以进入文本交互，而不只是孤立的数字 ID。
- 标题和描述**共享 embedding，但分别做平均池化**，再拼接。共享参数不等于丢掉字段身份。
  我们较新的单池化子词词袋模型，并没有完整复现这一设计。
- batch 实际在每轮训练**之前**翻倍，所以词稀疏网络使用的是
  4,000／8,000／16,000，而不是从 2,000 开始。
- 提交分支直接平均**对数价格预测**，再把还原的价格裁剪到 [3, 1000]。
  调试分支拟合线性回归，不代表提交使用了这些回归系数。

作者明确说，花了很多时间训练的强 LightGBM 没有改善融合。
经验是：单模型分数好，不代表它能提供其他模型尚未掌握的信息。
历史时间和裁剪阈值都是当时的选择，本轮不直接套用。

## 季军：保留有效符号，按品类调整融合

[bird 原帖][third]报告 CNN 约 .400、FM-FTRL 约 .415，融合却可到 public 约 .3905。
作者强调文本清洗同时改善两种模型。我们从中得到的判断标准是：
不能因为一个模型单独较弱，就不检验它的融合贡献。

[公开源码][third-kernel]里可看到：

- 统一重音字符，将 `+` 变为 `plus`，给部分符号保留词元；另一个神经预处理阶段
  会把部分独立的多位数字变为通用标记。我们的解释是：不同的不变性可以产生互补，
  但全局抹掉数字会损伤产品型号。因此本轮新视角保留精确数字。
- 不同的短卷积／attention 分支使用不同裁剪长度；训练改变样本切片和 batch，
  后段从 Adam 改为 Adagrad。这些是实现观察，作者没有给出独立消融，不能宣传成
  已证实的普适提升。
- 输出端把共同训练的线性、ReLU 和 Maxout 分支相加。这是另一个架构细节，
  不等于三个独立训练的融合成员，也没有证据表明移植后就能改善我们当前的网络。
- `catew` 按顶级品类给 CNN .50～.65 的份额，而非全部使用默认 .60。
  我们复用已有的 `ContextBlend`，通过样本量门槛和向全局权重收缩学习品类融合，
  不照搬手工权重表。
- 测试数据分块处理，控制内存；这对最终阶段更大的测试集尤为重要。

## 本轮实际融合了什么

新增[独立特征与实验模块](../mercari_top3.py)：

1. 新增互补的词法视角：重音折叠、标题／描述独立命名空间、`plus`／`heart`／
   货币／百分号词元、小数与字母数字拆分，以及结构化字段词元。
2. 新增“标题＋描述前 5 个词”的无序词对。默认最多 20 个不同词，
   因而每条记录最多 **190 个词对**。哈希限制维度和字典开销，代价是可能碰撞与截断。
3. 新增 (0, 200] 范围内的数字后继词特征，数值为 **log1p(数量)**，区分标题和描述。
   冠军原实现使用数量除以 200，重复词策略也不同；这里是独立改写。
4. 四组消融：纯词法、加词对、加数量词、全部加入。都在同一基础训练集上训练
   固定 alpha 20 的 Ridge，LSQR 容差 .002、最多 80 步。
   IDF 只拟合基础训练集；数量块不做行单位化，避免单个数量词的幅度被抹掉。
   特征不读取价格或行 ID。
5. 在 selection 上比较已有的和为 1、仿射、品类融合，并做分组后的半集检查。
   所有选择、权重和晋级决定都在打开审计标签**之前冻结**。

已有的独立／拼接／词干稀疏视角、二值／TF-IDF、Huber／软分桶、递增 batch、
稀疏行 Adam、产品统计和竞品校准继续保留。它们并不是这轮才实现的新成果。

## 完整基础集结果：词对有用，但融合扩展被拒绝

四组都使用 **1,186,026 条基础训练记录**，另有 74,129 条校准、74,126 条 selection、
148,254 条复用审计记录。新 Ridge 只拟合基础训练标签，没有采样；每个哈希块
262,144 列。

| 新专家 | Selection RMSLE | 复用审计 RMSLE | 拟合＋CSR 拼接 秒 | 三窗口推理 秒 | LSQR 步数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基础词法 | 0.496025 | 0.495846 | 3.78 | 0.044 | 26 |
| ＋无序词对 | 0.473492 | 0.472611 | 15.56 | 0.144 | 30 |
| ＋数量词 | 0.511224 | 0.512372 | 6.93 | 0.054 | 62 |
| ＋全部特征 | 0.496204 | 0.496618 | 17.74 | 0.132 | 64 |

词对相对这套基础词法模型，在 selection 改善 **4.54%**、审计改善 **4.69%**。
300 次配对行 bootstrap 的审计差值为 **-0.023235**，区间
**[-0.023861, -0.022735]**；仅针对这一次训练。
但它仍弱于已有强融合。数量词在本次哈希／线性 Ridge 设置下使两组原始模型都变差。
尺度／正则化、缺少非线性交互是待验证的解释，不能据此否定冠军在稀疏 MLP 上的结果。

**晋级门禁拒绝了本轮扩展。**完整池选择了带截距、权重和为 1 的融合，新增专家权重
几乎全部为零；仿射与品类融合在分组检查中也没有提供收益。
原 anchor 的 selection RMSLE 仍是 **0.382191247**，最终保留的审计 RMSLE 为
**0.380616255**。拟合池仅多了 -0.00009673 的微小截距，审计为 .380616369，
并未改善，因而没有替换旧方案。去掉任意一类新特征后结果在数值容差内相同。
输出的 `ensemble.npz` 与旧 anchor **逐元素完全一致**，不是只在六位小数上相等。
没有新增 Kaggle 提交或排名。

整轮增量运行 **211.59 秒**，其中特征准备
**151.16 秒**，进程峰值 RSS **2609.71 MiB**。
表中推理包含 296,509 条已准备记录的 CSR 拼接，不含文本提取；时间都是单次观察，
不是多次重复的平均值。运行环境为 4 核配额的 Linux，不分配 GPU；旧 anchor 的
完整训练成本不包含在内。

Selection 和审计窗口此前都被检查过。本轮先冻结再审计，不能把这些窗口重新变成
盲测集。保留原预测导致 bootstrap 差值为零，是构造结果，不代表泛化没有不确定性。
新增代码有 TDD 红／绿记录、真实 Ridge 学习、模型重载、非法输入／审计边界验证，
并测试晋级失败时完整保留旧预测。


验证：**161 个测试通过，其中 8 个为新增测试**。本次统计的 22 个 Mercari CPU
实验模块覆盖 **2,891／2,891 条语句（100%）**；新增模块为 **148／148（100%）**。
这是语句覆盖，不是分支或整个仓库的覆盖率。已有 Keras／NumPy、SVD 和 runpy
警告仍存在。CI 已加入这些测试和覆盖率门禁。

## 初学者怎么理解和复现

**RMSLE**：先把价格转为 log1p，再计算普通 RMSE。模型学习和融合的是对数价格，
最后用 expm1 还原。**词对**关注两个词是否同时出现，不要求挨在一起；
**数量词特征**关注有多少“什么东西”；**消融**是去掉一个组成部分，检验其额外贡献。
融合是否有效，还取决于模型的错误是否相似：权重和为 1 时，平方误差包含各模型
误差之间的乘积，不只包含各自的 RMSE。

准备完整的分组数据和旧最佳 anchor，参阅[小模型实验方法](SMALL_TEXT.zh-CN.md)和
[上一轮报告](SMALL_TEXT_REPORT.zh-CN.md)。数据、模型、运行产物继续由 Git 忽略。
完整复现 anchor 需要先完成它的上游专家训练，不能把下面的增量时间当作总训练成本。
只验证新专家流程时，也可以使用准备步骤生成、行 ID 对齐的基线 NPZ 作为 anchor。

```bash
python -m pip install '.[mercari,benchmark]' pytest pytest-cov
python -m pytest tests/test_mercari_top3.py \
  --cov=benchmarks.mercari_top3 --cov-report=term-missing --cov-fail-under=100
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
python -m benchmarks.mercari_top3 \
  --data-dir benchmarks/runs/mercari/frontier-001/data \
  --anchor benchmarks/runs/mercari/smalltext-t4-001/primary-blend/ensemble.npz \
  --output-dir benchmarks/runs/mercari/top3-reproduction-001 \
  --external-pretrained-data
```

小规模试跑可增加 `--rows 10000 --n-features 16384 --max-iter 20`，需要标明是采样实验。
每次使用新的输出目录。`--external-pretrained-data` 声明旧 anchor 的预训练来源，
新加入的四个专家自身不使用预训练权重。输出包括计划、冻结方案、报告、四组预测、
最终融合预测和可重新加载的本地可信 pickle 模型。本轮稀疏 CPU 流程不分配 GPU。

下一步合理候选是亚军的训练词典拼接规则、保留字段身份的共享 embedding 池化，
以及修复后的原生 FP16 小模型完整精度复测。这些尚未执行。
没有默认开启任意价格裁剪、全局数字屏蔽或刻意过拟合。

理论延伸：[特征哈希（Weinberger 等，2009）](https://arxiv.org/abs/0902.2206)解释
控制字典大小的取舍；[递增 batch（Smith 等，2018）](https://arxiv.org/abs/1711.00489)
提供训练计划的背景；[模型选择偏差（Cawley 与 Talbot，2010）](https://jmlr.org/papers/v11/cawley10a.html)
解释反复使用同一验证窗口的局限。本比赛具体技巧的证据仍是一手原帖与代码。
