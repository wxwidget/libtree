# 小文本模型、产品校准与 T4 原生精度实测报告

[English](SMALL_TEXT_REPORT.md) · [方法与运行命令](SMALL_TEXT.zh-CN.md) · [完整 JSON](smalltext-results.json)

2026 年 10 月 18 日，本地冻结融合 RMSLE 从 **0.380907 降至 0.380616**，
绝对改善 **0.00029060**，相对改善 **0.0763%**。300 次配对行 bootstrap 的差值
区间为 **[−0.00036465, −0.00021905]**。确认集此前已经反复看过，这是复核，
不是全新盲测、第一名或新的 Kaggle 成绩；已评分练习最佳仍为
**Private 0.39199 / Public 0.39110**。

本轮小模型单独表现偏弱，主要成功在于**条件校准、产品特征与硬件精度修复**。
T4 固定批量微基准中训练步改善 **3.31 倍**、推理批次改善 **2.70 倍**，
不能当成整套训练速度。上面的全量分数属于旧模拟 BF16 运行，修复后的原生 FP16
尚未完成全量质量重测，不会把微基准当成新模型精度。

## 小模型实测

基础训练 1,186,026 条，校准/选择/确认分别 74,129 / 74,126 / 148,254 条。
每个新神经网络上限 800 万参数，长度 96、回归头 128、种子 42。
词袋训练四轮、批量 2,048；小 BERT 三轮、批量 512。只用选择集挑检查点。

| 模型 | 参数量 | 选择 RMSLE | 确认 RMSLE | 平均每轮秒 | 三窗口推理秒 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 子词词袋 / MSE | 3,196,069 | 0.464184 | 0.462618 | 27.84 | 3.57 |
| 子词词袋 / Huber | 3,196,069 | 0.464129 | 0.462915 | 28.69 | 3.97 |
| BERT-tiny / MSE | 4,564,501 | 0.448773 | 0.447619 | 319.93 | 22.67 |

每轮包含训练与选择集评估；推理覆盖已编码的 296,509 条数据。单个 worker 总耗时
分别 676.90 / 683.64 / 1,536.34 秒，其中输入准备就占 561.61 / 564.59 / 553.52 秒。
短暂精度探针与 BERT 训练有重叠，时间是单次观测，不是跨硬件公平排名。
历史 MiniLM 选择 RMSLE 为 0.416930，但模型更大、长度 128、四轮且使用 A100。

词袋借鉴 fastText 的平均向量和哈希相邻词对，实际使用 WordPiece 子词，是独立
回归适配，不是官方 fastText 分类器或字符 n-gram 实现。小 BERT 曲线
0.475148 → 0.458221 → 0.448773，词袋最后一轮也仍在改善，说明预算内有欠拟合风险，
不能断言模型上限差。Huber 没有稳定击败 MSE，未根据确认集重新选轮数或损失。

## 融合与消融

残差校准只拟合校准窗口，输入来自未拟合这些标签的基础专家。旧完整校准方案
仅作外层锚点，不能把其校准集内预测当新校准特征。产品统计只在基础集拟合：
五种产品键、全局/品牌类别父先验、平滑 5/20/100，共 90 列。外层非负和为 1，
正则 1e-4，冻结前规定选择集至少改善 1e-5。

| 方案 | 选择 RMSLE | 确认 RMSLE |
| --- | ---: | ---: |
| 旧参考 + 三个原始小模型 | 0.382498 | 0.380907 |
| 旧参考 + 缓存 CPU 方案 | 0.382477 | 0.380894 |
| 旧参考 + 基本小模型校准 | 0.382440 | 0.380854 |
| 基本校准 + 缓存 CPU | 0.382397 | 0.380819 |
| 产品校准，不含缓存 CPU | 0.382233 | 0.380648 |
| **完整产品校准融合** | **0.382191** | **0.380616** |

15 个候选分支中 5 个权重大于 1e-8：旧参考 38.46%、产品 LibTree 深度 5
**26.59%**、LightGBM 20.10%、XGBoost 10.02%、缓存 CPU 4.84%。分支共享上游模型，
不等于五个独立模型即可从零训练。

三个小模型直接融合权重都是零，但其预测仍可作为条件信号：产品 LibTree 深度 5
在词袋 Huber、词袋 MSE、小 BERT 输出上分别分裂 38、50、129 次；8,616 次分裂中
1,042 次使用产品统计。这只是使用频次，不是因果重要度。移除这个 LibTree 分支，
重拟合选择集权重后，确认 RMSLE 回退到 **0.380675**。
[第一棵树文本](smalltext-calibration-tree-0.txt)标记了 LSA/产品/专家特征；32 个旧元特征
仍使用编号名。叶子是残差对数价格修正，需乘 .04 学习率，不是直接售价。

六个旧校准器在 296,509 条预测上精确重现。基本/产品版本基础混合权重与残差目标
完全相同，只改变树特征，维度 215 → 305。深树受益，深度 3 略退步。
扩展在看到较弱的选择曲线后加入，是适应性研究，不是预注册盲测；主方案先冻结，
随后消融未用于换方案。独立门槛计算列顺序与通用 runner 不同，优化器微小系数
差异约 1.8e-6；正式权重以确认审计前写下的 `primary.frozen` 为准，两者均通过门槛。

## 与竞品校准器比较

统一 400 轮、学习率 .04、CPU 四线程，但深度/叶子约束不同。秒数包含拟合、
三窗口预测与修正强度选择，不含特征准备或序列化；各一次，不是库的总体性能排名。

| 校准器 | 基本秒 | 基本确认 RMSLE | 产品秒 | 产品确认 RMSLE |
| --- | ---: | ---: | ---: | ---: |
| LibTree 深度 3 | 9.01 | 0.380946 | 10.39 | 0.380954 |
| LibTree 深度 5 | 12.12 | 0.381016 | 15.57 | 0.380905 |
| LightGBM 15 叶 | 11.17 | 0.380964 | 10.86 | 0.380855 |
| XGBoost 深度 4 | 10.55 | 0.381039 | 11.69 | 0.380847 |

基本视图中 LibTree 深度 3 有竞争力；产品视图中，LightGBM/XGBoost 单独效果和耗时
优于 LibTree 深度 5。本次可证明的 LibTree 价值是融合互补，不是普遍性能第一。
本轮未修改 C++ 学习器内核。

## 资源、成功和失败

一次完整 T4 实验加一次短硬件探针，累计约 52 分钟，所有实例及辅助 kernel 已释放。
观察余额 190.81 → 189.92 CU，约 .89 CU，余额经取整且不是最终账单。
旧专家训练成本不计入增量耗时。产品映射另占 **1,046,998,691 字节**磁盘，
800 万神经参数上限不代表整体融合轻量。

[缓存记录](smalltext-input-cache-001.json)：同机全量编码写盘 261.34 秒，五次
带哈希校验的热载入平均 0.86668 秒，数组完全相同。计时不含 TSV 读取；首次准备
有短暂本地测试重叠。它是输入复用效果，不是端到端 GPU 加速。

[原生精度记录](smalltext-native-amp-001.json)：T4 SM75 在同版 PyTorch 默认 BF16
支持为 true，原生支持为 false，旧选择实际使用模拟 BF16。修复后原生 FP16 的
训练步均值 116.69 → 35.28 ms，推理批次 30.53 → 11.31 ms；模型结构 456.45 万
参数、输入固定，权重随机初始化、目标合成，不涉及精度结论。A100 仍可用原生 BF16。

[数值失败记录](smalltext-precision-001.json)保留预设 .01 容差未通过：23/296,509
条输出超限，最大 .0165677。原 FP16 名称已纠正为模拟 BF16，原数值未改动。
对每个窗口最差四条、共 12 条用原始批量核查：输入相同、旧 AMP 精确复现，
GPU FP32 与 CPU FP32 最大差异 4.77e-7。不能推广成所有 FP32 输出误差上界。
需要更严格数值复现时可显式用 `--precision fp32`。

大部分品类改善，但缺失类别与低价区间存在退步，完整分组结果见 JSON。
bootstrap 不能消除反复选择带来的偏差，也不是多随机种子训练置信度。
没有达到第一或额外 10% 效果提升。原生 FP16 完整质量复测和符合赛事要求的源码
重训尚未完成，因此本轮不触发新 Kaggle 提交。

## 复现与学习

先读[初学者指南](BEGINNER_GUIDE.zh-CN.md)、[运行方法](SMALL_TEXT.zh-CN.md)
及[原全量实验准备](FRONTIER.zh-CN.md)。当前 master 使用校验缓存与原生 AMP；
复现原始精度与耗时需使用 `3828d76`。旧完整模型和 CPU 分支需按已有流程重训，
或恢复可信旧工件；这次是增量复用实验，不是完整系统从零训练计时。

```bash
python -m benchmarks.mercari_colab --gpu T4 --profile smalltext \
  --data-dir prepared-windows --output-dir new-colab-study \
  --cli colab --include-models
# 将新专家目录追加到原 frontier calibrate 命令。
# 对比相同命令加 --product-views；外层使用旧最佳作 baseline，
# ensemble 加 --external-pretrained-data，不能把校准内预测当新拟合特征。
```

[完整 JSON](smalltext-results.json)保存哈希、配置、源码版本、学习曲线、消融和
冻结权重。数据、模型权重、统计映射和原始预测均忽略 Git。
理论与 API 引用见[方法页](SMALL_TEXT.zh-CN.md)。
本地 **41 项测试、六模块 845/845 条语句覆盖**，
[实现提交的四项 CI](https://github.com/wxwidget/libtree/actions/runs/39148472156)全部通过，
包括已有原生 sanitizer 与覆盖检查；不等于全仓库分支/GPU 指令覆盖。
