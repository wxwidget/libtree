# Mercari：文本表示、真实 GPU 训练与模型融合

[English](FRONTIER.md) · [此前已评分方案](TECHNICAL_REPORT.zh-CN.md) · [零基础指南](BEGINNER_GUIDE.zh-CN.md)

本轮探索精细文本处理、LSA、预训练向量、T4/A100 神经网络和树／回归模型融合。
此前实际最好成绩仍为 **private RMSLE 0.39199、public RMSLE 0.39110**。
本地验证不等于 Kaggle 分数，更不等于已经取得第一名。


## 本轮结果：2026 年 10 月 18 日

冻结方案的本地复核 RMSLE 从 **0.394153 降至 0.380907，相对下降 3.36%**。
尚未提交新的 Kaggle 预测；不能据此宣称超过历史 private 第一名 0.37758。
新方案还需要完整重训和统一的推理／提交管线，才能获得实际榜单成绩。

| 方案 | 选型 RMSLE | 复用窗口的复核 RMSLE |
| --- | ---: | ---: |
| 此前冻结方案 | 0.395662 | 0.394153 |
| 新基础模型融合 | 0.383569 | 0.382011 |
| 加入残差树的完整融合 | **0.382498** | **0.380907** |

[预先冻结的方案](frontier-pre-audit-protocol.json)按照选型分数选择完整融合，
之后才读取本轮复核标签。绝对差为 −0.0132466；300 次配对行 bootstrap 的
95% 差值区间为 [−0.0139295, −0.0125207]。这是固定模型、复用窗口的条件区间，
不是训练种子的稳定性，也不是全新盲测结果。

| 冻结 MiniLM＋Ridge，alpha 10 | T4 编码、CPU 回归 | 0.624249 |
| 冻结 MiniLM＋LightGBM | T4 编码、CPU 树 | 0.469991 |

微调 MiniLM 的单模型分数仍弱于原有整体方案，但它在新基础融合中获得 28.06% 权重：

### 消融：去掉一类新增专家会怎样

所有变体在本轮复核前列入方案。只移除指定的新增专家预测，重新选择融合权重；
其他专家固定，原方案保留，整个表都不包含新的残差校准器。

| 基础融合变体 | 选型 RMSLE | 复核 RMSLE | 相对完整基础融合变差 |
| --- | ---: | ---: | ---: |
| 全部新增基础专家 | 0.383569 | 0.382011 | — |
| 去掉监督 MiniLM | 0.388317 | 0.386233 | +0.004222 |
| 去掉全部新增稀疏网络 | 0.388572 | 0.387386 | +0.005374 |
| 去掉词干化稀疏网络 | 0.384731 | 0.383319 | +0.001308 |
| 去掉联合文本稀疏网络 | 0.383897 | 0.382403 | +0.000392 |
| 去掉分字段稀疏网络 | 0.383658 | 0.382075 | +0.000063 |
| 去掉 CNN／GRU | 0.383755 | 0.382246 | +0.000235 |
| 去掉冻结向量预测 | 0.383569 | 0.382011 | 约 0 |
| 去掉 LSA 独立预测 | 0.383569 | 0.382011 | 约 0 |

这些变化不能相加。最后一行没有移除向量树内部使用的 LSA 元数据。
完整融合的外层预测列消融保留了已训练校准器，而校准器仍依赖上游模型。
所以外层权重为零，不等于已经省掉相应推理成本。本轮没有完整服务延迟或剪枝加速结论。

### LibTree、LightGBM、XGBoost 和回归

相同的 74,129 条校准数据、212 个输入特征、残差目标和 400 轮树：

| 校准模型 | 选型 RMSLE | 复核 RMSLE | 观察到的阶段秒数 |
| --- | ---: | ---: | ---: |
| LibTree，深度 3 | 0.382686 | 0.381065 | 7.43 |
| LibTree，深度 5 | 0.382712 | 0.381064 | 12.53 |
| LightGBM，15 叶 | 0.382704 | 0.381051 | 15.52 |
| XGBoost，深度 4 | 0.382725 | 0.381162 | 13.50 |
| 非负 Ridge，alpha 10 | 0.383773 | 0.382065 | 0.15 |
| 非负 Ridge，alpha 100 | 0.383767 | 0.382059 | 0.19 |

LibTree 的选型点估计最低，LightGBM 的复核点估计最低，差距很小，不能宣称算法优越性。
计时包括拟合和预测，期间还并行运行本地测试，且模型容量不同，不能作为公平速度排名。
最终融合同时使用三种树，因此整体提升不能全部归因于 LibTree。
[实际残差模型第一棵树的文本](frontier-tree-example.txt)和
[JSON](frontier-tree-example.json)展示了可解释的分裂条件。
它只解释 400 棵修正树中的一棵，不是整个神经网络融合的完整解释，更不是因果解释。

### GPU、成本与工程验证

| 阶段 | 硬件 | 单次观察秒数 |
| --- | --- | ---: |
| 冻结 MiniLM 编码 | T4，float32 | 1,094.69 |
| 冻结向量及所有预测头，整个 worker | T4＋CPU | 2,225.65 |
| 分字段稀疏网络，3 个专家 | A100 80 GB | 380.08 |
| 联合文本稀疏网络，3 个专家 | A100 80 GB | 536.74 |
| 词干化稀疏网络，3 个专家 | A100 80 GB | 522.77 |
| 监督 MiniLM，4 轮，整个 worker | A100 80 GB | 1,157.47 |

worker 时间包含特征、训练、预测和写文件，不含申请机器及数据上传下载。
每个配置只拟合一次，所以这里只报告原始耗时，不用中位数，也不虚构重复训练的均值或加速比。
账户计算单位从 199.27 到 190.81，这是账户观察值，不是每个模型的精确账单。
所有本轮创建的会话已释放，最终 API 使用速率为零。

本地 **93 个不同测试全部通过，14 个 Mercari 模块的 1,835 条语句覆盖率为 100%**；
另用编译模式重新执行 4 个 FM 测试。此范围不代表整个仓库或分支覆盖率 100%。
真实 T4 启动器还完成了小型合成数据的 float16 微调、下载、清理，不把它当作效果评测。

集成阶段发现并修复了两个行覆盖率未暴露的问题：源码打包假定存在 LICENSE 文件，以及
`python -m` 将元数据类保存为 `__main__.ListingInputs`。测试现已覆盖真实仓库打包和模块入口；
此前自有模型的原始元数据保留，另外生成兼容副本，预测和权重没有更改。
TensorFlow CPU／T4 的 128 行重放最大对数差为 4.77e-7；Torch CPU float32 与
A100 bfloat16 为 0.00538，因此后者只能说近似兼容，不能说逐位一致。

本轮部分稀疏 GPU 权重未保留，预测和报告已保存。以后运行可加 `--include-models`。
晋升为新的打榜方案之前，仍要完成重训、统一导出与新提交，不能用本地分数替代榜单结果。

## 目标与实验边界

我们根据商品标题、描述、品牌、类别、成色和运费预测价格。
先学习 `log1p(price)`，再用 `expm1` 转回价格。RMSLE 衡量对数价格误差，越小越好。

比赛在 2018 年结束，现在属于赛后练习。此次下载的 **public** 榜单 CSV 中，
领先分数为 **0.37665**；最终榜单为 **0.37758**，与冠军公开的带有 `Δpub` 列的
[最终榜单截图](https://github.com/pjankiewicz/mercari-solution/blob/master/presentation/img/leaderboard.png)一致。
目标参考值为 **private 0.37758**，不混用 public 与 private。
本轮允许现代 GPU 和外部预训练模型，不代表复现当年的 CPU、时间等限制。

## 每种文本方法在学什么

| 方法 | 可以怎样理解 | 局限 |
| --- | --- | --- |
| TF-IDF／二值词袋 | 为词和短语建立一列，保留型号等精确信息 | 特征很多，相近词未必相互理解 |
| 联合文本 | 用字段标记组合标题、品牌、描述和类别 | 要证明其额外融合价值 |
| LSA | 将词共现压缩为少量连续坐标 | 可能丢掉稀有但影响价格的型号或容量 |
| MiniLM | 用预训练网络，把语义相近的文本放在相近位置 | “手机壳”和“手机”语义接近，价格却相差很多 |
| 商品属性 | 识别容量、数字、配件、损坏、套装、全新等词面线索 | 不是核实过的商品事实 |
| CNN／GRU | 结合价格标签学习短语或词序，再结合类别嵌入 | 网络复杂不保证更准，必须检查过拟合 |
| 稀疏 MLP | 在词袋上学习非线性交互 | 输入稀疏不代表优化器的内存与计算一定稀疏 |

`LatentText.topics()` 可以查看每个坐标较大的词权重，帮助理解共现模式，
但不能解释价格的因果关系。原有 LibTree 树结构、预测路径和残差解释仍可使用。

## 怎样避免提前泄露答案

相同商品字段组成同一组，避免重复商品跨越不同窗口：

| 窗口 | 行数 | 用途 |
| --- | ---: | --- |
| 基础训练 | 1,186,026 | 拟合词表、SVD、类别字典和专家模型 |
| 校准 | 74,129 | 学习基础专家之后还剩的误差 |
| 选型 | 74,126 | 选择轮次、修正强度和融合权重 |
| 复核 | 148,254 | 方案冻结后评估，不参与拟合 |

所有零价格样本保留。发送给 Colab 的复核文件没有价格列。
预测文件必须携带完全一致、顺序一致的商品 ID，否则拒绝融合。
先写入冻结方案，再读取复核标签评分。

复核窗口在此前研究中已看过，所以明确称为**复用的审计窗口**，不宣称是全新盲测。
配对 bootstrap 只估计固定模型在这些样本上的抽样波动，不能抵消反复选模型的偏差，
也不代表不同训练随机种子的波动。

## 融合不是模型越多越好

如果不同模型总在同一类商品上犯同样的错误，增加数量的价值有限。
我们在选型窗口学习非负、总和为 1 的权重，并轻微约束其偏离原方案的程度。
没有增益的模型允许权重为零；报告保留误差相关性和去掉单个专家的消融。

二层树使用未经过原修正器的专家预测、LSA、数值统计、商品属性和新预测，
只用校准标签学习残差。LibTree 两种深度、LightGBM、XGBoost 使用相同输入比较。
修正强度从 `0、0.25、0.5、1` 中选择，复核标签不参与选择。

## 已观察到的成功与失败

- 64 维 LSA＋LightGBM 两个配置的选型 RMSLE 为 **0.493827、0.486604**，
  原有整体方案为 **0.395662**。LSA 不适合直接替代精确词特征，只有额外融合增益才值得保留。
- T4 上 CNN 最佳选型 RMSLE 为 **0.427283**，GRU 为 **0.424239**。
  后期训练误差下降、验证分数却变差，因此保存较早的最佳轮次。
- GPU 暴露了 CPU 测试没有发现的问题：Keras 自动启用 XLA，但稀疏算子无法完成编译。
  现显式设置 `jit_compile=False`，仍使用 GPU 支持的计算，并新增模拟自动 JIT 偏好的训练测试。
- 高内存 Colab 冷启动超过 SDK 默认等待时间；本云机启动器延长连接就绪等待到 120 秒，
  保留 TLS 和认证校验。失败会话已释放。

单模型分数不能直接证明组合优于原方案。不同架构、批大小、硬件和库版本的时间不能直接相除。
重复计时使用平均数、最小／最大值、标准差和原始样本，保留慢的异常情况。

## 如何复现

[英文实验说明](FRONTIER.md#reproduce-the-study)提供完整可复制命令，顺序为：

1. 在 CPU 开发环境安装 `.[mercari,benchmark]`，准备官方 `train.tsv`。
2. 用 `optimized-config.json` 重训冻结的基础方案，或复用本云机已有模型。
3. 执行 `benchmarks.mercari_frontier prepare`，生成固定窗口、基线预测和输入哈希。
4. 本地执行 `trees`，训练 LSA＋Ridge／LightGBM。
5. 登录官方 Colab CLI，运行 `benchmarks.mercari_colab`。
   `--profile all` 跑序列网络与 MiniLM；`--profile sparse --gpu A100` 比较两种稀疏文本视角。
   `--profile stemmed` 比较词干化视角；`--profile transformer --transformer-epochs 4` 做监督微调。
6. 解压结果，执行 `calibrate`，最后运行一次 `ensemble` 冻结并复核。

每次使用新输出目录。数据、模型、预测、上传分块和日志放在 Git 已忽略的 `benchmarks/runs/`。
GPU VM 不安装 CPU 专用的 TensorFlow 组合，使用其 GPU 版本并记录实际设备。
`--allow-cpu` 仅用于小规模功能测试，不能作为 GPU 证据。

Colab 启动器记录哈希，分别保存执行、下载、清理状态，在 `finally` 中只释放自己创建的会话。
如果本地进程被强制杀掉，应根据 `job.json` 手动确认并释放会话。
某个模型失败，不会因为其他模型留下结果文件就算成功。

## 新增表示和监督微调

词干化视角把 `running shoes` 和 `run shoe` 合并，并把 `iPhone6S 64GB case`
转换为 `iphon 6 s 64 gb case`。独立字符通道保留型号、容量等精确信息。
规则结果使用有上限的缓存，不读取价格，也不估计推理批次的统计信息。
在宽度、损失、优化日程和随机种子相同的两个配置中，词干化表示组合的最佳单模型为
**0.407484**，联合文本组合为 **0.409622**；这不是仅改变词干化一个因素的结论。

监督 MiniLM 同时更新预训练主干和价格预测头，结合均值／CLS 池化、6 个类别嵌入及数值属性。
最大长度 128，批大小 512，主干初始学习率 `3e-5`、预测头 `.001`，每轮减半。
A100 使用 bfloat16 计算、float32 损失及梯度裁剪。两轮实验从 **0.440837** 改善至
**0.423849**；独立的四轮实验为 **0.439640 → 0.423525 → 0.419540 → 0.416930**。
不能把通用向量的语义相近等同于价格相近。

模型初始化的固定版本为 `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`。
独立 Torch 测试环境验证真实小型 BERT 的学习、主干参数更新、填充屏蔽及检查点重放。
核心 LibTree 用户无需安装 Torch；实验复现命令及可选依赖见英文说明。

不同损失的配置还同时改变了随机种子或二值／TF-IDF 输入，不能把差异单独归因于损失。
同样，冻结向量＋LightGBM 与端到端微调的预测头和元数据处理也不同。
完整方案的外层预测列消融保留已训练校准器，不能等同于移除其上游模型；
不含新校准器的基础融合消融更适合解释新增模型的独立贡献。
