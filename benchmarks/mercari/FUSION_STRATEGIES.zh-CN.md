# 单层线性、多层 MLP、按条件线性融合实测

[English](FUSION_STRATEGIES.md) · [完整结果](fusion-strategies-results.json) · [冻结输入](fusion-candidates.json)

## 比较什么

比较同一批模型预测经过三种外层融合后的效果和成本。输入共 **72 列缓存预测**：
25 列 frontier、13 列小文本／商品校准、26 列 CPU 视角、6 个新增稀疏模型和
2 个稀疏残差分支。这不是 72 套独立完整模型；不少共享底层模型，或者只改变
残差强度，误差存在强相关性。

“单层”指本次新增的外层融合，输入本身仍可包含神经网络或残差树。没有根据
独立分数筛掉弱模型。另外去掉六个新增稀疏模型及其两个残差后代，形成 64 列
的家族消融；不能把这个整体消融解释为某一个 Lasso／Elastic Net 的因果贡献。

已在 selection 上拟合最终权重的聚合模型，包括当前最佳 anchor，不进入训练
输入。输入清单记录了预测文件 SHA-256、矩阵列号、家族、声明的训练阶段和四个
数据文件哈希。这些阶段来自可信的本地实验记录；哈希只能核对文件身份，不能
单独证明训练历史。

## 三种策略

初学者可以这样理解：全局线性对每个商品都使用同一套专家权重；MLP 在隐藏层中
学习非线性交互，ReLU 把负值变为零、保留正值；条件线性在样本足够的每个品类里
仍使用可直接阅读的线性公式。参数更多能增加表达能力，也更容易拟合噪声。

| 策略 | 对数价格上的形式 | 固定设置 |
| --- | --- | --- |
| 单层全局线性 | `z = sum(w[j] * p[j]) + b` | 非负权重、和为 1；截距限制 ±.25；平方对数误差及 1e-4 正则 |
| 多层 MLP | `z = 训练标签均值 + 标准差 * MLP(标准化预测, 品类独热编码)` | 两个 ReLU 隐藏层：32、16；线性输出；Adam .001；批量 512；sklearn L2 alpha .1 |
| 分条件线性 | `z = sum(w[品类,j] * p[j]) + b[品类]` | 全局权重作为先验；品类训练行数至少 2,000 才学习局部权重；局部正则 .01；小类／未见品类回退全局 |

全局单层使用 `RmsleBlend`。条件模型使用已有的 `ContextBlend`，其全局模型是
`RegularizedBlend`：非负权重，总量允许在 [.8,1.2]，截距 ±.25，正则 .001。
额外加入同一种全局模型作为 **affine 线性对照**，避免把线性约束变化误认为
品类条件带来的收益。它属于诊断对照，不参加三种主策略的晋级选择。

MLP 和条件线性使用相同的、无标签的商品一级品类；全局模型按定义对所有品类
共用一套权重。三者拿到相同的预测列。MLP 直接预测对数价格，不额外连接最佳
模型，也不叠加残差树。最终用 `expm1(max(z, 0))` 还原价格，评分采用相同截断。

这里比较实际策略，不是单独验证隐藏层的作用：MLP 相对全局线性还增加了品类
信息，不能把全部收益都归因于“多层”。MLP 与条件线性共享这份上下文；若要单独
归因于网络深度，还需要只输入预测、不输入品类的 MLP 对照。

## 验证流程及限制

保留原来的四个窗口：base 1,186,026、calibration 74,129、selection 74,126、
confirmation 148,254。本次不重训底层专家。把 selection 按重复商品特征分组，
再划成约 **60% 融合训练／20% MLP 检查点调优／20% 策略检查**，种子为 703/704。

1. 融合权重、标准化参数、品类词表只学习融合训练窗口。共同的正则参考列也
   仅依据该窗口确定，不用策略检查标签来挑参考。
2. MLP 只在调优窗口选择检查点：最多 100 轮，连续 12 轮无至少 1e-6 RMSLE
   改善就停止，并恢复最佳检查点。运行 42、43、44 三个种子检查稳定性；
   **预先指定 42 为主模型**，不会事后挑最好的一次。
3. 三个主策略在策略检查窗口比较。差距不超过 1e-5 时依次优先选全局线性、
   条件线性、MLP。64 列消融不参与主模型选择；三个 MLP 的平均预测仅作诊断。
4. 然后在完整 selection 上重训每种策略。MLP 使用已经冻结的训练轮数，不再
   早停。全部模型、权重、选择与晋级状态写入 `frozen.json` 后，才读审计标签。
5. 所选方案需要在策略检查和完整 selection 上都比旧方案改善至少 1e-5，才
   通过最终晋级检查；否则输出与旧方案完全一致。旧方案只作为独立参考。

**这仍是复用本地数据的条件审计，不是全新无偏的泛化评估。** 历史底层模型的
参数、检查点、部分上游混合权重曾依据 selection 选择，confirmation 也已被
多次查看。拆掉聚合输入、分开本次元模型的数据职责，不能消除过去的适应性复用。
旧方案外层权重还曾直接拟合策略检查行，所以其检查分数属于历史训练内结果。
可以说本次新增融合模型在选择策略时没有拟合自身的检查标签，不能说整个流水线
是全新盲测或完整 OOF，也不能据此推算新的 Kaggle 得分。

## 实测结果

主候选池含 72 列。融合训练／检查点调优／策略检查的实际行数为
**44,477／14,825／14,824**。所有融合模型在完整 74,126 行 selection 上重训，
并冻结后，才查看 148,254 行审计数据。

| 融合方式 | 策略检查 RMSLE | 重训后审计 RMSLE | 融合训练 + 重训秒数 | 推理平均秒数 |
| --- | ---: | ---: | ---: | ---: |
| 单层全局线性 | 0.387702 | 0.380609 | 0.674 + 0.908 | 0.038 |
| MLP 32/16，种子 42 | 0.387926 | 0.379886 | 5.202 + 4.879 | 0.486 |
| 分条件线性 | 0.388067 | 0.380704 | 1.415 + 1.845 | 0.148 |
| 全局 affine 对照 | 0.387766 | 0.380725 | 0.612 + 0.717 | 0.020 |

**审计集上，MLP 在三种主策略中最好**，比单层线性降低 **0.190%** RMSLE。
配对按行 bootstrap 的 RMSLE 差值 95% 区间为 **[-0.000985，-0.000502]**。
这只针对该次训练和复用数据，不包括种子方差及适应性选择的不确定性。
按行 bootstrap 也把审计行视为独立，没有按重复商品组重采样。
本次 MLP 的调用耗时约为单层线性的 **12.9 倍**。

**冻结前的策略检查选择的是单层线性。** 它的输出为 **0.380608699**，旧方案
为 **0.380616255**，差值仅 **-0.000007555**；区间
**[-0.000051356，+0.000045556]** 跨过零。它通过预先约定的本地 selection 门槛，
但不足以证明相对旧方案有可靠提升。旧方案文件保持原样。不能因为后来发现 MLP
审计分数更好，就回头改写冻结选择。没有产生新的 Kaggle 提交或得分。

| MLP 种子 | 选中的轮数 | 审计 RMSLE |
| --- | ---: | ---: |
| 42 | 36 | 0.379886 |
| 43 | 39 | 0.381149 |
| 44 | 34 | 0.380159 |

三个单模型分数的**算术平均**是 **0.380398**，标准差 **0.000543**，
最差 **0.381149**。三个模型**对数预测的平均**为 **0.379682**，
较单层线性降低 **0.243%**。这是诊断组合，不是冻结前选中的方案。
该三模型组合另一次计时的平均为 **1.010 秒**，最大
**1.043 秒**，标准差 **0.025 秒**，并验证与保存预测
精确一致。它与前面的单模型计时不在同一轮；缓存和系统状态会改变耗时，不能相除
就声称精确的并行或批处理加速。

| 融合 | 平均秒数 | 最大秒数 | 标准差秒数 |
| --- | ---: | ---: | ---: |
| 单层线性 | 0.038 | 0.069 | 0.020 |
| MLP 种子 42 | 0.486 | 1.183 | 0.312 |
| 条件线性 | 0.148 | 0.166 | 0.017 |
| affine 对照 | 0.020 | 0.023 | 0.002 |

所有调用都保留，包含慢样本。MLP 有一次 1.183 秒，其余五次约 .334–.374 秒。
全局 simplex 和 affine 使用相同的向量加权预测核，不能把这次均值差解释为
算法效率的区别。缓存、内存、调度都是可能因素，本次没有定位具体成因。
上述耗时倍数只描述这些观测，不是稳定的硬件性能保证。

推理均覆盖 **222,380 行**（selection + 审计），两次等价流程共记录六次调用，使用两个 CPU 线程，
输入是缓存底层预测和品类字符串。包含 MLP 标准化和独热编码；不包含原始文本
处理、模型加载及底层专家推理。JSON 保留全部采样值、最大值和标准差。
各模型训练／重训时间是两次观测的平均；MLP 三个种子共六次种子／流程观测的训练加重训耗时
平均 **9.806 秒**、标准差 **1.165 秒**、最大
**11.791 秒**。

完整重训后的条件模型实际学习八个品类的局部权重。它略好于全局 affine 对照
（**0.380704 对 0.380725**），但没有超过更简单的 simplex 线性融合；
相对 affine 的配对区间为 **[-0.000079350，+0.000033579]**。
因此不能把不同约束与正则带来的差异全部归因于“按品类”。

从可解释性看，全局 simplex 有十个实际非零权重；条件模型公开全局和八个品类的
权重集合；MLP 则不容易直接解释。JSON 记录实际权重、品类系数和 MLP 参数量，
不会从分数反推重要性。

**稀疏家族消融（审计）：**

| 融合方式 | 全部 72 列 | 去掉 8 列新增稀疏及后代 |
| --- | ---: | ---: |
| 单层全局线性 | 0.380609 | 0.380609 |
| MLP 32/16，种子 42 | 0.379886 | 0.380026 |
| 分条件线性 | 0.380704 | 0.380690 |

八列新增稀疏输入的全局线性权重接近零，MLP 仍可间接利用它们。但平均收益很小，
并非每个种子都改善；删列还会改变输入维度和随机初始化路径，所以这个家族消融
不能当作因果特征重要性。

MLP 在这 11 个品类中的 10 个改善，电子类变差。误差较高的古董收藏、缺失品类
没有隐藏。已独立用各品类行数和平方误差重构总体 RMSLE。

核验流程 **113.72 秒**，首次实验 **108.94 秒**，
记录的实验阶段合计 **222.66 秒**，进程 RSS 峰值 **1313.9 MiB**，
包含元模型训练、完整重训、重复推理、保存产物和 bootstrap；排除模块导入及
复用底层工作的成本。单独的三模型组合计时、编辑和回归测试不在这些计时内。
最后将参考文件读取与训练资格校验分开，去掉参考读取器上不准确的临时训练阶段
标记，再核验全部 12 个模型在两个窗口的输出逐位一致；轮数、选择和分数都没有变化。
两次计时流程并不增加独立的精度重复实验数量。

完整重训后排序发生了反转。固定轮数在更大训练集上还会增加 Adam 更新：融合训练
每轮 87 个批次，完整 selection 每轮 145 个批次。这是可能的影响因素，不能据此
证明反转的成因。下一步应通过重复／嵌套分组验证或新盲测确认，而不是在本次审计
数据上挑种子。

最终 CPU 优化回归 **183 项测试通过，208.64 秒**。25 个模块的
**3,347/3,347 条语句覆盖率 100%**，新增融合模块为 **221/221**。
TDD 验证留出数据上的非线性／品类互补、训练窗口预处理、最佳检查点恢复、固定轮数
重训、序列化／预测精确重放、训练阶段／ID／哈希／有限数值边界、参考读取与训练
资格分离、分组职责隔离、先冻结后审计及精确回退。还用官方公式独立重算全部
12 个模型输出及品类汇总；两次流程的模型系数与输出逐位一致。输出另有 492 条
既有警告。这里只指 CPU 优化测试范围内的语句覆盖，不代表全仓库、分支或 GPU
覆盖率。**数据核验结论：可带限制分享**，需保留历史 selection／审计复用的说明。

## 复现与检查

从仓库根目录运行。先安装依赖，并按前面的 [Frontier](FRONTIER.zh-CN.md)、
[小文本](SMALL_TEXT_REPORT.zh-CN.md)、[CPU 多视角](CPU_MULTIVIEW.zh-CN.md)、
[稀疏模型](SPARSE_PENALTIES.zh-CN.md)、[残差融合](RESIDUAL_FUSION.zh-CN.md)
实验准备缓存产物。数据、大模型、凭据不进 Git；本次提交输入清单和报告。

```bash
python -m pip install '.[mercari,benchmark]' pytest pytest-cov
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 python -m benchmarks.mercari_fusion \
  --data-dir benchmarks/runs/mercari/frontier-001/data \
  --manifest benchmarks/mercari/fusion-candidates.json \
  --anchor benchmarks/runs/mercari/smalltext-t4-001/primary-blend/ensemble.npz \
  --output-dir benchmarks/runs/mercari/fusion-strategies-reproduction
```

输出目录必须是新目录。提交的清单复放本次确切缓存，不会把任意重训模型当作同一
文件。若重新训练的随机模型哈希变化，应使用新产物的实际 SHA-256 和真实训练阶段
重新生成并检查清单。每个专家项包含 `name`、`path`、`sha256`、`fit_window`
（`base` 或 `calibration`）、`family`、可选的矩阵 `column`。预测档案需要
`selection`、`confirmation` 和有序对齐的 `*_ids`。不能把直接在 selection 上
拟合的聚合模型改标为 base 来绕过检查。

每个候选池保存 `models.pkl`（输入列顺序和六个融合模型）、带 ID 的预测档案及
完整的训练／早停历史；顶层保存 `plan.json`、`frozen.json`、`report.json`、
`ensemble.npz`。使用模型前按保存的 `names` 排列预测列。报告包含推理时间的
算术平均、完整样本值、最大值和标准差，三个种子的波动、配对比较，以及全部
审计品类，包括样本少或误差高的类别。总体 RMSLE 是按行汇总平方对数误差再开根，
不能把品类 RMSLE 直接平均。

```bash
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 python -m pytest \
  tests/test_mercari_fusion.py --cov=benchmarks.mercari_fusion \
  --cov-report=term-missing --cov-fail-under=100
```
