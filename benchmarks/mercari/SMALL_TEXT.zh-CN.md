## 模型与控制变量

固定三个候选，不无限搜索：

| 候选 | 特征与损失 | 最多轮数 | 批量 |
| --- | --- | ---: | ---: |
| 子词词袋回归 | 48 维 WordPiece 向量、32,768 个哈希相邻词对桶；MSE | 4 | 2,048 |
| 子词词袋回归 | 相同结构；Huber | 4 | 2,048 |
| BERT-tiny | 2 层、128 隐藏维预训练 BERT；MSE | 3 | 512 |

统一序列长度 96、输出头宽度 128、CPU 线程设置 4、随机种子 42。
800 万参数上限包含类别嵌入与回归头；超限在批量编码和训练前报错。
Colab CPU 处理数据与分词，T4 负责混合精度训练和预测。

词袋模型借鉴 [Joulin 等人的 fastText 思路](https://aclanthology.org/E17-2068/)，
使用平均向量与哈希词对。这是独立的 PyTorch 价格回归实现，**不是官方
fastText 分类接口**；使用 WordPiece 子词，也不是 fastText 的字符 n-gram。
分词器预训练，回归词向量随机初始化。小 BERT 参考
[Turc 等人](https://arxiv.org/abs/1908.08962)，使用预训练骨干。
两者差异同时包括预训练和架构，不能据此单独归因于某一因素。

学习目标为标准化的 `log1p(price)`。MSE 对应平方对数误差；Huber 是抗异常值
备选，不等于直接最小化 RMSLE。模型还输入训练集拟合的品牌/类别嵌入、
新旧程度、运费、长度和产品词语标记。详细学习率和优化器设置见英文页。

## 复现

先按[原实验](FRONTIER.zh-CN.md)准备分组数据并完成官方 Colab CLI 授权。

```bash
# 本地 launcher / 测试使用 CPU Torch；Colab 保留其预装 GPU Torch。
python -m pip install 'torch==2.9.0+cpu' --index-url https://download.pytorch.org/whl/cpu
python -m pip install '.[mercari-transformer]' pytest pytest-cov
python -m benchmarks.mercari_colab \
  --data-dir benchmarks/runs/mercari/frontier/data \
  --output-dir benchmarks/runs/mercari/smalltext-t4 \
  --cli colab --gpu T4 --profile smalltext --include-models
```

输出目录须为新目录。逐个候选的执行命令与测试命令见[英文页](SMALL_TEXT.md)。
CPU 机器可加 `--allow-cpu` 执行独立 worker，CUDA 可用时仍优先使用 GPU。
不要把 OAuth 凭证写进命令、代码或 Git。

## 编码缓存

初次远程实测使用 `3828d76`，逐个候选重复准备数据。当前 launcher 在同一实例中
共享输入缓存，独立 worker 可用 `--cache-dir` 指定缓存目录。缓存键包含所有窗口的
文件哈希、分词器固定版本、长度、编码源码和依赖版本；载入前校验 16 个数组及
输入映射的文件哈希。身份不符、内容损坏或写入中断均拒绝复用；中断后换新目录。
独占创建目录可防止多个写入者互相覆盖。缓存不存储价格回归模型。

内存映射采用写时复制，模型不能修改缓存磁盘内容。CPU 测试验证两种架构在缓存
前后的训练输出完全一致。缓存只能读取自己生成的可信文件，哈希不能认证恶意
pickle。原始 GPU 耗时没有享受此缓存，不会改写成缓存优化后的成绩。

## 已测的缓存成本与精度差异

[完整缓存记录](smalltext-input-cache-001.json)：在本机相同 CPU 配额下，全量
1,482,535 条数据首次编码及写盘 261.34 秒，五次热缓存校验载入均值 0.86668 秒，
所有数组完全一致，缓存 593,380,496 字节。计时不含 TSV 读取和分词器创建。
首次准备期间有约 14 秒本地测试重叠，且仅测一次；不能称为整套训练的公平加速比。
缓存键随后又加入 Python 和窗口读取源码，进一步防止错误复用。

[数值复现及 GPU 核查](smalltext-precision-001.json)保留了一次失败：同一词袋
检查点，CPU FP32 与 T4 自动 AMP（模拟 BF16） 在 296,509 条预测中有 23 条超过预设 0.01 容差，
最大差异 0.0165677 对数价格，平均绝对差异约 0.00096；没有放宽容差掩盖问题。

在同一个 T4 实例上另开短暂 kernel，对各窗口最差的四条数据，用原始 2,048
批量做受控核查：输入逐项相同，GPU 自动 AMP 精确复现旧输出；关闭 TF32 后，GPU
FP32 与 CPU FP32 在这 12 条上的最大差值为 4.77e-7。这支持差异来自混合精度，
不是缓存改变输入；不能推广成全部 FP32 预测均有该误差上界。辅助 kernel 已删除。

新 worker 增加 `--precision fp32`，可显式使用全精度训练和推理；默认 `amp`
现已按原生硬件能力选择 BF16 或 FP16。原实测仍是 AMP 成绩。单模型推理观测为 CPU FP32 7.95 秒、T4 AMP
3.57 秒，不含准备输入，不能当成端到端或同硬件同精度性能排名。

融合命令可用 `--external-pretrained-data` 明确声明所有上游预训练依赖，
避免冻结基线文件名隐藏 MiniLM 后被错误标成“不含预训练”。这只影响报告元数据。
另有 14 项 frontier 测试，372/372 条语句覆盖；两组共 41 项、相关六模块 845 条。

## 产品特征校准扩展

`mercari_frontier calibrate --product-views` 在原有元特征上加入 90 个产品统计量：
五种产品身份近似键 × 均值/支持度/离散度 × 全局/品牌类别父先验 × 平滑 5/20/100。
全部映射只在基础训练窗口拟合并保存，确认文件含价格时拒绝执行。方法复用
[已有 CPU 实验](CPU_MULTIVIEW.zh-CN.md)，参考
[Micci-Barreca](https://doi.org/10.1145/507533.507538)。

这个扩展在观察到小模型选择集曲线较弱后加入，尚未查看本轮确认分数；属于适应性
研究，不是预注册盲测。比较相同容量的校准树在有无产品特征时的表现。
外层共 15 个分支：历史最佳、三个小专家、六个基本校准器、四个产品校准树及
缓存 CPU 多尺度融合。分支共享上游模型，不等于 15 个独立拟合模型。
正系数 Ridge 不使用产品列，因此不把重复版本加入外层。

## T4 原生混合精度修复

前面的探针把自动 AMP 变量叫作 FP16，名称不准确。后续用相同 PyTorch
2.11.0+cu130 的 T4 验证，默认 BF16 检查为 true，但排除模拟支持后为 false。
因此初次全量实测实际使用的是**模拟 BF16**；数字和失败记录保持原样，精度名称
已更正。现在 helper、梯度缩放开关与报告均调用
`is_bf16_supported(including_emulation=False)`。T4 用原生 FP16，A100 可用原生 BF16。
参考 [PyTorch API](https://docs.pytorch.org/docs/stable/generated/torch.cuda.is_bf16_supported.html)。

[真实 T4 微基准](smalltext-native-amp-001.json)使用相同 456.45 万参数 BERT-tiny
回归结构、固定真实编码输入、随机初始化及合成零目标；不是新的精度实验。
预热五步后，每种模式各记录 20 个同步训练步及 20 次推理批次：

| 精度 | 平均训练步 ms | 平均推理批次 ms | CUDA 已分配峰值 MiB |
| --- | ---: | ---: | ---: |
| 旧模拟 BF16 | 116.69 | 30.53 | 966.83 |
| **修复后原生 FP16** | **35.28** | **11.31** | **786.28** |
| FP32 | 66.20 | 21.34 | 1,082.09 |

固定工作负载中训练步约 **3.31 倍**、推理批次约 **2.70 倍**，FP16 输出有限，
记录期间梯度 scale 稳定为 65,536。这不是端到端加速或精度不变的证明。
初次全量分数仍属于旧模拟 BF16 方案，修复后完整 FP16 质量尚未重新测量。
两个实例及临时诊断 kernel 均已释放。
