01 · The data

Start with a table

Each row is one example, each feature column describes it, and the target is the answer we want to predict.

Example: house prices

Size (m²)RoomsPrice ($k)

Features: size and rooms. Target: price. Training gives examples with known answers.

Two supported tasks

Regression Predict a number, such as price or cost.

Binary classification Estimate the probability of one of two labels, such as churn yes/no.

Classification labels must be 0 or 1. Text categories need numeric encoding first.

Vocabulary: a feature is an input clue; a label or target is the answer; a prediction is the model's estimate.
02 · Decision trees

A tree asks simple questions

A decision tree asks questions such as “is size at most 5?” Each answer sends a row left or right. A leaf holds the final prediction. Drag the threshold below to see how one toy split groups examples. This is an illustration, not benchmark data.

feature ≤ threshold → left child; otherwise → right child

A shallow tree is easy to explain. A deeper tree can describe more patterns, but may memorize noise in training data.

03 · Boosting

Boosting builds a team of small trees

One small tree is often too simple. Gradient boosting adds trees sequentially. After each tree, it measures what errors remain; the next tree learns a correction for those errors.

prediction = starting value + learning rate × (tree 1 + tree 2 + …)

For a number

A later tree can add a positive correction where the current estimate is too low, or a negative correction where it is too high.

For a probability

Trees adjust a score called a margin. A sigmoid function maps the final score to a probability from 0 to 1.

Why sequential? Tree 2 depends on errors left by tree 1. Boosting rounds cannot all train at once, though independent work inside a round can run in parallel.

How does a split get scored?

The learner sums gradients and Hessians (curvature of the loss) in each candidate child. It favors a split that improves the objective while applying an L2 penalty. A child below min_samples_leaf is rejected. The algorithm notes show the equations.

04 · Efficient learning

Histograms reduce split-search work

A naive tree may try every distinct feature value as a threshold. LibTree instead chooses up to max_bins quantile cut points and stores compact bin numbers. It scans per-bin gradient sums to evaluate candidate splits.

Change the bin count in this simplified teaching diagram. Fewer bins mean a coarser search; more bins mean finer candidates and more work. The values and equal-width groups below are illustrative.

05 · Missing data

Missing values get a learned route

Use NaN for a missing numeric feature. During split search, LibTree checks whether missing rows should go left or right. The better direction is stored in the tree and used at prediction time.

Infinity is invalid. Do not fill missing values using statistics computed from the full dataset before splitting; that lets test data influence training.

Text categories need encoding. Fit the encoder on training rows only; ignore categories seen only in the test fold. The benchmark pipeline shows this pattern.

06 · Evaluation

Training score is not the final score

Overfitting means learning patterns that work on training examples but fail on new ones. Keep examples out of training and use them to estimate generalization.

  1. Split data before fitting preprocessing.
  2. Fit the model and encoder on training data.
  3. Use validation data to choose settings.
  4. Use the final test set once; do not tune on it.

The following curves are a conceptual illustration, not LibTree results. Deeper trees often lower training error; test error can eventually rise.

Useful metrics

  • RMSE: typical regression error in target units; lower is better.
  • ROC-AUC: binary ranking quality; higher is better, 0.5 is random ranking.
  • Log loss: probability error; lower is better and confident mistakes cost more.
  • Train/test gap: compare the same metric for both sets. A gap is a signal to investigate, not a diagnosis by itself.

For binary labels 0/1, use GBDTClassifier and predict_proba. Try the CLI with ./build/xgbt --help; exact CSV options are in the CLI guide.

07 · First model

Run LibTree with Python

python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
import numpy as np
from libtree import GBDTRegressor

# Four rows, one numeric feature
x = np.array([[0], [1], [2], [3]], dtype=np.float32)
y = np.array([0, 0, 1, 1], dtype=np.float32)

with GBDTRegressor(min_samples_leaf=1) as model:
    model.fit(x, y)
    print(model.predict(x))
    print("last training loss:", model.training_loss_[-1])

For binary labels 0/1, use GBDTClassifier and predict_proba. Try ./build/xgbt --help. The CLI guide includes a complete train and predict example with valid CSV files.

08 · Parameters

Change one setting at a time

Select a parameter to see its usual effect. Compare validation quality and runtime; these are tendencies, not guarantees.

Increase…Common trade-off
DepthCaptures more patterns; can overfit and costs more.
Number of treesAdds more corrections; increases training and prediction time.
Learning rateLarger steps learn faster but can be less stable.
BinsOffers finer split candidates at extra training cost.
Minimum leaf rowsAvoids tiny leaves but can miss rare patterns.

Start with defaults, keep the split and seed fixed, and change one setting at a time. LibTree currently has no early stopping.

09 · Architecture

How LibTree is organized

Interfaces

Python, C ABI, C++ API, and CLI validate their inputs at the boundary. All use the same native learner.

Training core

C++ validates arrays, bins features, builds histograms, selects splits, updates predictions, and records loss. RAII containers own scratch memory.

Parallel work

A bounded thread pool is reused. Independent histograms, eligible nodes, and prediction batches can run concurrently. Boosting rounds keep their dependency order.

Prediction

Trees store split features, thresholds, children, leaf values, and missing directions. Shallow trees can use a contiguous compiled layout.

Why not linear speedup? Some work stays sequential. Small tasks cannot amortize dispatch, and CPU quota or memory bandwidth limits parallel work. LibTree keeps small jobs on the serial path.

10 · Quick check

Check your understanding

Why fit an encoder only on training rows?
Using held-out categories or statistics leaks information from evaluation data into training.
Can all boosting trees train independently?
No. Each new round depends on errors from earlier rounds. Some work inside a round can run in parallel.
Which data chooses hyperparameters?
Validation data. Keep the final test set out of model and preprocessing choices.
