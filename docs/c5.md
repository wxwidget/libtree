# C5-style classification: a beginner's guide

[中文](c5.zh-CN.md) · [Interactive rule explorer](C5_GUIDE.html) ·
[Comparison and ablations](../benchmarks/C5_REPORT.md)

`C5Classifier` is an independent numeric binary/multiclass classifier. It
combines weighted decision trees, discrete SAMME boosting, post-pruning, and
faithful IF–THEN rules. Explanations list the rules actually matched by a sample
and add their votes to reproduce its prediction.

This is C5-inspired, not a C5.0 implementation or file-format clone. Histogram
thresholds and cost-complexity pruning replace C5.0's confidence-factor/global
pruning. Categorical subset splits, winnowing and C5.0 rule optimization are
outside this implementation [1, 2]. No C5.0 source is incorporated.

## Your first model

Install with `python -m pip install .`, or build the checkout and set
`PYTHONPATH=python`. Python needs NumPy; training runs in C++17.

```python
import numpy as np
from libtree import C5Classifier

# Columns: balance, days late. Teaching data, not an evaluation.
x = np.array([[500, 0], [100, 1], [200, 2],
              [500, 20], [100, 25], [200, 15]], dtype=np.float32)
y = np.array(["repays", "repays", "repays", "late", "late", "late"])
with C5Classifier(n_estimators=5, max_depth=3, min_samples_leaf=1) as model:
    model.fit(x, y)
    print(model.classes_)  # late=0, repays=1
    print(model.dump_rules(feature_names=["balance", "days_late"]))
    print(model.explain([200, 15], ["balance", "days_late"], format="text"))
    explanation = model.explain([200, 15])
    assert explanation["predicted_label"] == model.predict([[200, 15]])[0]
```

The tree separates days late at 2. A pure first tree ends boosting early.
The rule `days_late <= 2 OR days_late IS MISSING` predicts class 1. Missing
routing is learned; ties choose left. Inspect such behavior before using a
model. Text shows label mappings; Python JSON includes `class_labels` and the
explanation's `predicted_label`. Native records use integer class indices.

`X` is `(rows, features)`; `y` is one-dimensional. Python maps finite numeric or
string labels to sorted `classes_`; native labels are contiguous integers
`0..K-1`, K<=256. One-class datasets produce constant models. Numeric features
support NaN, reject infinity. Encode categories using training data only and
preserve column order when predicting.

## Trees, boosting and pruning

A **decision tree** asks questions such as “days late <= 2?”. Its **leaf**
selects the largest weighted class. `sample_weight=` lets observations have
different importance. **Boosting** trains trees sequentially, increasing the
weight of previously misclassified samples. For K classes and weighted error e,
discrete SAMME [3] gives an accepted tree:

```text
vote = learning_rate * (log((1 - e) / e) + log(K - 1))
misclassified sample weight *= exp(vote)
normalize sample weights to sum to 1
```

Trees must beat random classification, e < 1-1/K. Later weak trees are discarded
and stop training; an unusable first learner becomes a majority model. Perfect
trees stop training, with error clipped to 1e-15 for a finite vote. A one-class
model has vote 1. Class ties choose the lowest index. `n_estimators=1` disables
boosting; `estimator_errors_` contains each accepted tree's weighted error,
not final ensemble error.

**Pruning** replaces a subtree with a leaf when that does not increase:

```text
weighted training misclassification error + pruning_alpha * leaf_count
```

Weights are globally normalized per round. Bottom-up decisions minimize this
objective over subtrees of the grown tree. Alpha=0 disables post-pruning;
larger alpha favors fewer rules. This uses the cost-complexity principle [4],
with misclassification risk. sklearn `ccp_alpha` uses its chosen impurity;
equal numeric alphas do not imply equal pruning. Select alpha on validation
data, never the final test set.

## Split criteria

| Criterion | Meaning | Tradeoff |
| --- | --- | --- |
| `gain_ratio` (default) | Information gain / split entropy | C4.5-inspired normalization with a low-gain guard |
| `entropy` | Reduction in class uncertainty | Direct information gain |
| `gini` | Reduction in class mixing | Avoids logarithms |
| `hellinger` | Class-conditional branch distance | Binary imbalance; see [risk methods](c5-risk.md) |

Entropy is `-sum(p log2 p)`; Gini is `1-sum(p²)`. Gain ratio divides entropy
gain by binary split entropy. Each feature supplies its best eligible ratio
split; its gain must also exceed the mean gain of eligible feature candidates.
This is an explicit histogram approximation, without all C4.5 threshold/MDL
corrections [1]. The experiment report evaluates all three criteria.

## Read rules and explanations

Each retained leaf gives one rule. Repeated feature conditions merge into an
interval `lower < value <= upper`. Missing membership is a separate bit.
Exactly one rule matches per estimator. Sum the matched `vote` by class and
select the largest. These rules faithfully describe the model; they are not
surrogates, per-feature SHAP values or causal claims.

`dump_rules("json")` returns a **JSON string**; `explain(sample)` returns a
**dictionary**. Schema version is 1.

| Field | Meaning |
| --- | --- |
| `rule_id`, `estimator_index` | Stable indices in this fitted model |
| `conditions` | Feature index/name, nullable lower/upper bounds, `accepts_missing` |
| `support` | Training rows reaching the leaf, including zero-weight rows |
| `weighted_purity` | Leaf majority weight / leaf weight in that boosting round |
| `vote` | Estimator vote, not a leaf probability |
| `observations` | Used features' observed values; NaN becomes JSON null |
| `votes`, `prediction` | Class vote totals and winning class index |
| `probabilities` | Same uncalibrated scores as `predict_proba` |

Probabilities are `softmax(votes / sum(votes))`, using max-subtraction. This
conservative transform differs from sklearn SAMME probabilities and C5.0
confidence estimates. Its binary maximum is about 0.731, even for a perfect
training tree. Evaluate ROC-AUC, accuracy and calibration separately; calibrate
on an independent validation fold if needed. Purity is not future accuracy.

Text thresholds have float32 round-trip precision; vote/purity annotations have
four significant digits. JSON preserves double precision. Labels are escaped.
All rules are exported; depth, estimator count and pruning control complexity
without hiding the ensemble. Rule/condition counts are readability proxies;
no human comprehension study has been conducted [7].

## Parameters, performance and lifecycle

Defaults: 10 estimators, depth 6, bins 64, minimum leaf rows 5, rate 1,
alpha .001, minimum gain 1e-9, gain ratio, one thread. Depth 0 permits a stump;
caps are depth 32, bins 256, estimators 1000, threads 256. Validation limits
are 100 million rows and 100,000 features, not a memory-capacity promise.

Unweighted global quantile thresholds are built once on training data. uint16
column-major bins are reused across boosting rounds; histograms use current
sample weights. Learned missing directions follow [5]; histogram efficiency
follows [6]. Features parallelize at `rows*features >= 65536`. Boosting rounds
and dependent nodes stay sequential. Ordered reduction gives identical results
for one/four threads. Only sufficiently large training data creates a pool;
with that pool, prediction parallelizes at `rows*accepted_estimators >= 65536`.
Small jobs run serially. Inference reuses one vote buffer per worker; pruned
subtrees are compacted away. Contiguous float32 avoids conversion copies.

`get_params`/`set_params` configure the next fit. Failed fits preserve the old
model. `close()` or context managers release memory/workers. Concurrent readers
are supported; do not refit/close during reads. C5 persistence and native
categorical splits are not provided in this version. Rule JSON is an inspection
format; GBDT's `xgbt` persistence is separate.

## C++ and C ABI

```cpp
#include <iostream>
#include <vector>
#include "libtree/c5.h"

int main() {
  std::vector<float> x{0, 1, 2, 3};
  std::vector<int> y{0, 0, 1, 1};
  libtree::C5Parameters options;
  options.min_samples_leaf = 1;
  libtree::C5Classifier model(options);
  model.Fit({x.data(), 4, 1}, y);
  model.DumpRules(std::cout, libtree::DumpFormat::kText, {"days_late"});
  model.Explain({x.data() + 3, 1, 1}, std::cout);
  return model.Predict({x.data(), 4, 1}) == y ? 0 : 1;
}
```

Link with `-std=c++17 -Iinclude build/libtree.a -pthread`. Fit accepts optional
`vector<double>` weights. `rules()`/`Explain()` return typed records.
`PredictProba()` returns row-major rows*K doubles. Separate `LtC5*` C handles
use `LtLastError()` and caller-owned buffers. Query inspection size with null
output and capacity 0; allocate that many bytes including the NUL terminator.
Never pass a C5 handle to a GBDT function. Input buffers must live during calls;
the model does not retain them after fitting.

## Command line

```sh
PYTHONPATH=python python -m libtree rules --train labeled.csv --header \
  --rounds 10 --depth 4 --criterion gain_ratio --alpha .001 --threads 4 \
  --feature-names balance,days_late --format text > rules.txt
PYTHONPATH=python python -m libtree explain --train labeled.csv --header \
  --sample 200,15 --feature-names balance,days_late --format json
python -m libtree --help
```

Commands fit fresh models from numeric CSV, with labels in column 0. Python API
also accepts string labels. Use `nan` for missing sample values. Other options
include `--min-leaf`, `--bins`, `--rate`, `--min-gain`. `xgbt` serves GBDT models.
