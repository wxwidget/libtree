# 算法原理、性能设计和贡献指南

[English](design.md)

## GBDT 在学习什么

模型输出 `F(x) = base + eta * sum(tree(x))`。回归初始值为训练标签均值；
二分类初始值为均值的 log odds，计算前将均值限制在 `[1e-6, 1-1e-6]`。
二分类最终概率为 `sigmoid(F)`。每轮根据损失的一阶和二阶导数生成树：

| 目标 | 梯度 g | Hessian h | 展示的训练损失 |
| --- | --- | --- | --- |
| 平方误差的一半 | F − y | 1 | 均方误差 MSE |
| logistic 交叉熵 | sigmoid(F) − y | p(1 − p)，最小 1e-6 | 平均交叉熵 |

叶节点汇总 `G = sum(g)`、`H = sum(h)`，叶节点输出为 `−G/(H + lambda)`。
划分增益为
`0.5 * (G_L²/(H_L+lambda) + G_R²/(H_R+lambda) − G²/(H+lambda))`。
只有增益超过 `min_gain + 1e-12` 且左右节点均满足最少样本数时才接受划分。
遍历顺序固定，因此相同数据得到相同结果。深度从根节点的 0 开始计算。
训练更新和预测时均将每棵树的输出乘一次学习率。

每列只在训练开始时排序一次，选取确定性的分位数切点，合并重复切点。
这里使用完整排序列的分位数采样，并非 XGBoost 的加权近似 sketch。
特征值映射为 uint16 分箱编号，0 专用于 NaN。每个节点扫描样本编号，汇总
各特征的梯度、Hessian 和计数；通过前缀和评估切点，并分别尝试将缺失值
分配到左右子节点。最大观测值也作为候选切点，因此常量观测值仍可以与
缺失值分开。没有缺失值时跳过重复方向，全部缺失的特征无法划分。

## 性能设计准则

- 准备阶段和提升轮次分开：只排序、分箱一次，后续轮次复用结果。
- 分箱采用按列连续存储的 uint16，每个值 2 字节；输入为借用的行优先
  float32 矩阵，不为每个样本单独分配对象。
- 梯度和 Hessian 用 double 汇总；稳定 sigmoid 和 softplus 避免 exp 溢出
  或 log(0)。切点直接使用观测值，避免极端 float 的中点计算溢出。
- 仅原地划分样本编号。构造较小子节点的直方图，再从父节点相减得到
  较大子节点；按递归深度复用缓冲区。
- 低基数列跳过最常见分箱，通过节点总量恢复；双值列用连续掩码加权
  求和避免离散写入，四个独立累加器降低加法依赖。父节点分箱已为常量的
  列直接使用子节点总量，避免再扫描。
- 宽且以连续变量为主的矩阵使用行优先直方图索引，一次读取梯度服务
  多个特征。窄矩阵、类别变量较多或直方图超过 65536 项时按列扫描。
- 补齐查找表后用固定步长确定分箱，不改变原有分位切点。到达叶节点
  就更新对应样本的 margin，避免再次遍历新树；训练损失与下轮导数
  共享稳定指数函数结果。
- 一棵树使用一个连续节点 vector 和整数子节点索引。递归期间不保留可能
  因 vector 扩容失效的引用；所有权通过 RAII 管理，不使用递归裸指针图。
- 浅树编译为隐式完整树：8 字节划分节点、连续的加权叶值和缺失方向
  位标志。提前结束的叶值覆盖其补齐子树；数组内容不超过原节点存储，另有每树
  固定的 vector 元数据开销。深度
  超过 8 或过于不平衡的树保留普通遍历。
- 每批处理 64 行，复用热树数据并让独立路径交错执行。保持 double
  累加及树的顺序；`PredictInto` 和 C ABI 直接写入调用者输出，Python
  预测不再经过额外的原生结果分配和复制。
- 预留有界空间；构建复用有效输出。不使用 fast-math、关闭校验、特定 CPU
  指令要求或全局随机状态。
- 核心不依赖 Python、XGBoost、OpenMP，使用标准 C++ 线程可选并行，默认单线程。

排序准备成本为 `O(d n log n)`；每轮约为
`O(d n depth + d B nodes)`，另需更新预测值。推理为
`O(n_test * trees * depth)`。训练临时空间为 `O(n d + n + d B * depth)`，另加模型。
原矩阵由调用者提供；列分箱每个值 2 字节，宽矩阵路径另有每项 2 字节的
行优先直方图索引，还包括稀疏例外行编号及按深度分配的直方图缓冲区。
不复制原始特征矩阵。
每棵树的最大节点数为 `min(2n−1, 2^(depth+1)−1)`，必须结合可用内存设置
合理深度和轮数；该实现不是 out-of-core 学习器。

优化按工作负载实测筛选，保留独立单层树数学校验、序列化模型普通遍历
校验、优化前后的逐值预测检查、缺失值行为和两种接口。性能测试使用
Release 构建并检查效果。排名仅适用于记录的数据、参数、硬件和线程数，
不能证明所有任务都更快。

## 确定性并行

`num_threads` 包含调用线程。可复用线程池最多启动 `num_threads - 1` 个工作线程，
静态分配连续任务区间；每个工作线程拥有独立排序缓冲区。直方图按特征分配，
各分箱内部仍按原始样本顺序累加。宽矩阵大节点让各线程处理一组连续特征，
在组内复用同一行的导数，小节点保留串行内核；不需要共享直方图原子加法，也不改变浮点归约顺序。Boosting 各轮、
划分选择、样本分区和深度优先构树仍按依赖顺序执行。根节点和较小子节点已算出的
统计量直接复用，减少重复扫描而不改变计算顺序。

特征任务少于 65,536 次样本/特征访问时串行；预测校验在 65,536 个值开始并行，
预测批处理在至少 512 行、8 棵树时并行，每批 64 行，各线程写入不同输出区间。
阈值是工作负载经验值，不能保证所有机器都最优。树的 double 累加顺序保持不变。
协调线程等待全部任务结束后才读取结果或重新抛出异常。任务描述在栈上，
线程池就绪后的有效 `PredictInto` 调用不分配堆内存。

同一模型的并发预测共享线程池，分发排队，避免内部线程数无限增长。不能同时修改
线程数、拟合或销毁模型。RAII 负责等待线程退出；拟合、加载失败保留旧模型。
复制模型可共享线程池，但模型数据独立。模型格式仍为版本 1，不保存线程数；
C ABI 保留旧创建函数，增加 `LtSetNumThreads`。

排序缓冲区增加 `O(n * threads)` 临时空间，线程栈也有开销；应按 CPU 配额和外层
并发任务分配线程。小数据训练可能因启动、同步开销而变慢。ThreadSanitizer
验证任务同步及并发预测；ASan/UBSan/LSan 检查内存和生命周期。覆盖率使用原子
GCC 计数器和新的 profile，防止并发测试破坏采样计数。

## Google 风格和明确的例外

格式遵循仓库 `BasedOnStyle: Google` 配置；使用命名空间、自包含且有保护
宏的头文件、命名结构体、enum class、C++ 类型和方法的 UpperCamelCase、
成员的 `snake_case_`、const 视图、清晰的所有权，并将编译警告视为错误。
Python 遵循 PEP 8 命名。

Google 内部 C++ 指南禁止异常。本公共库明确选择标准异常处理 C++ 输入
错误，并保证训练失败时保留旧模型；C ABI 捕获异常，不允许异常跨越 C/Python
边界。这是明确的风格例外，不宣称完全符合 Google 内部规则。
基准中的动态加载和函数指针转换限于 Linux 互操作边界。核心使用 RAII；
C ABI 的 opaque handle 必须配对释放，是有文档说明的所有权边界。

## TDD 和验证

1. 先在 C++ 或 Python 测试中定义行为并确认失败。初始空实现首先未通过
   “未训练不能预测”的检查，随后实现通过了测试。
2. 实现最小改动，跑针对性测试，通过后再执行 `make test` 和重构。
3. 内存相关改动运行 `make sanitize`。原生测试包含 100 次 C ABI 分配释放
   和随机稠密数据训练；Python 交替显式关闭与自动回收 300 次，并检查
   RSS 稳定性，容许 16 MiB 波动。RSS 仅为粗略保护，不能替代 LSan。
4. `make coverage` 对 C++ 源文件设置 100% 行覆盖率门槛，另生成 Python 报告。
   gcov 的模板异常处理可能显示重复行，报告仍统计它们，不只统计算法核心。
5. 算法或性能改动后运行比较，保留每次原始结果、数据 SHA256、工具版本、
   CPU、线程数、效果指标和简单基线。

独立的单层树 oracle 穷举合法划分，直接计算平方残差，不复用训练器的
增益公式。1 万行性能保护同时检查效果和 30 秒的宽松训练时间上限，用于
发现严重退化，不用于判断细微速度差异；正式基准使用未见过的测试样本。

C/C++ 调用者必须提供有效句柄、缓冲区容量和生命周期，无法检查任意指针
是否有效。预测输出不能与特征缓冲区重叠。训练和返回 vector 的 `Predict`
会分配内存，`PredictInto` 对有效输入仅使用栈上临时空间。原生训练失败
保留旧模型。C ABI 失败返回 −1 或空句柄，需立即读取 `LtLastError()`；
不可重复使用已释放句柄。Python 通过 `weakref.finalize` 和幂等 `close`
管理资源，不能在同一模型上同时拟合、关闭和预测。
